# Type-pairing specs

Generated by the 15-agent type-pairing fan-out.


## DISPLAY+BODY PAIRING — Bela Bereka 700 (display, calligraphic, Bold-700-only) ↔ Noto Sans Ethiopic 400/500/700 (bilingual body/UI), plus the four candidate display voices scored against Noto body.

**Verdict:** Bela Bereka 700 ↔ Noto Sans Ethiopic is a sound, intentional display/body pair — calligraphic heritage voice over a neutral bilingual reading face — and the only reason it is metric-safe is the 22px floor plus the single-language display rule, which guarantee the two faces never share a baseline or a text run. The 700-vs-400 weight contrast is correct and earned (max 2 display moments per viewport). Adopt NO candidate as a second display: Zemenay (duplicative serif voice) and Agbalumo (wrong temperature, single-weight 400) are rejected; Monolithic Geez is rejected on license + numeral-role collision; Ge'ez Manuscript Zemen earns only a conditional Amharic-only pull-quote slot with a strict co-presence ban against Bela. Recommended lineup: Bela alone as primary, no accent. Two pairing-decisive defects to resolve before ship: Bela's Latin set is un-audited, and the spec contradicts itself on who owns the hero numeral (HH Lemd tabular vs Bela proportional).

**Spec:**

THE PRIMARY PAIR — Bela Bereka 700 ↔ Noto Sans Ethiopic

Weight contrast (700 display vs 400 body): CORRECT and required. Editorial display faces are set heavier than body; 700/400 is the canonical news hierarchy, and here it is earned rather than assumed: the system caps Bela at 2 display moments per scroll-viewport (one h1, one pull-quote) and bans it below 1rem and from the terminal. Because Bela is Bold-700-ONLY, the system physically cannot slide toward "display at 500" — the single weight is a restraint mechanism, not a limitation. Noto's own internal ladder (400 body / 500 inline-Geez gloss / 700 uppercase label) supplies every mid-step, so body-adjacent hierarchy never needs Bela. The only genuine risk was overuse + uppercase/tracking on a calligraphic face, which the spec already bans — the contrast is right BECAUSE the scarcity is enforced.

x-height: NEUTRALIZED, not matched. Bela's calligraphic fidel and Noto's fidel (large central bands) have different optical bands, and Noto's Latin x-height (~0.54em) is not Bela's — but this never matters, because the two faces never share a line. The rules that do this work: (a) single-language headlines (data-lang toggle, never mix scripts at display size); (b) the only permanent script pair — the wordmark ማለዳ (Noto Sans Ethiopic) + Maleda (Bela 700) at 1.25rem — is already baseline-joined with a 0.6em gap, so the join is engineered, not improvised; (c) the 22px floor guarantees Bela never sits on a body line. Read that floor as a PAIRING device, not just a readability floor: it is what makes the x-height question structurally moot. Below 22px Bela's joins and the 7 vowel-row diacritics degrade; 22px keeps ~11-12px of stroke detail on the fidel — correct and even generous.

Mood (calligraphic heritage vs neutral humanist sans): the intended tension, not a conflict. Bela is the "Ethiopian soul," Noto is the "modern bones" — the identity's own dialectic, and the reason articles read as gallery text rather than utility text. Conflict would only appear if Bela were used small (banned), tracked/uppercased (banned), or for labels (banned — labels are Noto 700 at 11px). The one hierarchy collision to watch is internal to Bela, not the pair: the pull-quote (clamp 1.375–1.75rem = 22–28px) and h2 (clamp 1.75–2.375rem = 28–38px) share the 28px step, same face, same weight — they must never co-occur in one view region. The spec's 2-display-moments cap already prevents this; keep it.

Honest caveats that keep this from being a clean pass:
1. Bela's LATIN set is un-audited and unverifiable via public listing (the "Berka" I found is a different Latin-only face). If Bela's Latin is weak or derived, English h1s and the wordmark's "Maleda" inherit that weakness. This is the load-bearing un-audited assumption of the entire display voice — deepen target 1.
2. The h1→lead step is a four-axis cliff: Bela 700 calligraphic lh 1.05 at 40-60px drops to Noto 400 neutral lh 1.55 at 18-21px. That is an acceptable editorial drop, but if it ever reads abrupt the fix is to bridge with the pull-quote or the 11px kicker — never to lighten Bela (it has no lighter weight, and that is the point).

ALTERNATIVES SCORED AGAINST NOTO BODY

Zemenay (editorial serif-ish, OFL): REJECT. As a primary it displaces Bela — already chosen. As an accent it is duplicative: an editorial serif + a calligraphic display is two competing display identities, and a serif reads "newspaper of record," which dilutes the manuscript-gallery voice rather than extending it. There is also no empty slot in the ladder for it — the dek/lead is Noto 400, the pull-quote is Bela, the label is Noto 700. Adding it means inventing a role it doesn't have. The system's worst enemy is a second display voice.

Agbalumo (wide warm rounded, OFL): REJECT, on corrected facts — it DOES carry Ge'ez (Google Fonts `ethiopic` subset, plus Latin/Cyrillic-ext/Vietnamese), so script coverage is not the argument against it. Reject on (a) mood/temperature: it is a curvy, chunky, brush-pen "charming and playful" single-weight display; against umber/parchment/gold restraint and Bela's angular calligraphy it reads retail/casual — the same "horrendous shapes" temperature in display form; (b) single weight 400: a wide rounded display at 400 is the weakest possible display voice and would need even more size to hold hierarchy against Bela 700; (c) it is a second hand-drawn voice competing with the first — two brush-pen displays is incoherence, not range.

Ge'ez Manuscript Zemen (OFL, 4107 glyphs, COLR, authentic manuscript): CONDITIONAL REJECT. Structurally it is the SAME role as Bela (calligraphic heritage display), so as an accent it is redundant — two calligraphic faces would fight for the same pull-quote and initials moments, and both would be "heritage," which is the definition of no hierarchy. It is also the least legible of the candidates at the exact stress zone (authentic manuscript calligraphy has low stroke contrast and tight joins at 22–28px), and its COLR color tables add rendering weight to a themable light/dark system. It earns only a narrow, strictly-bounded slot: Amharic-only heritage pull-quotes, never co-rendered in the same viewport as Bela, gated behind a COLR-on-parchment/dark rendering audit. Otherwise run Bela alone.

Monolithic Geez (squared architectural, proprietary): REJECT on two hard grounds, though it has the best IDEA of the four. It is the only candidate structurally CONTRASTIVE to Bela (squared/monumental vs organic/calligraphic) — that is the correct theory of an accent: not another calligraphic, but a "modern bones" counterpoint. But (a) proprietary license in an OFL-anchored system is a blocker (HH Lemd's license is already an open risk; never add a second), and (b) role collision: its natural home — big editorial numerals and section initials — is already owned by HH Lemd (every numeral, including the hero) and the Ge'ez section chips (fidel initials). Its best role is redundant before it ships. Note for the future: a squared-monumental OFL face would be the one defensible accent direction.

RECOMMENDED DISPLAY LINEUP

Primary: Bela Bereka 700 — CONFIRMED, unchanged. Calligraphic heritage over neutral bilingual reading face, 700/400 contrast earned by scarcity, metric-safe by construction (22px floor + single-language rule + engineered wordmark baseline).
Accent: NONE — run Bela alone. The identity's "heritage accent" is already delivered by design elements — the illuminated frame, headpiece interlace band, Ge'ez section chips, gold knot — not by a second display face. The system's own laws ("one memorable thing," max 2 display moments per viewport) argue against a second voice, and every candidate either duplicates Bela's calligraphic role or fights the restrained temperature. If a future mandate forces an accent, the only defensible adoption is Ge'ez Manuscript Zemen in the Amharic-only pull-quote role under a strict co-presence ban with Bela — never co-render in one viewport.

Pairing-decisive pre-ship blockers:
1. Audit Bela's Latin set and the wordmark baseline join (deepen target 1).
2. Resolve the hero-numeral ownership contradiction (deepen target 2) — my lean is HH Lemd 400 tabular 40-52px panel-gold on umber, which is consistent with "HH Lemd owns every number" and Bela's terminal ban; the Live-data §6 "Bela at 44px proportional figures" line is a leftover of an earlier design.


## DATA pairing — HH Lemd Mono × Noto Sans Ethiopic × the numeral grammar × ahabesha'stypewriter × the terminal ladder

**Verdict:** The two monos coexist, but only as a hard script partition (Lemd owns every Latin character and numeral; Noto Sans Ethiopic owns every fidel — never the reverse), and the pairing is optically coherent ONLY if the fidel stay labels, never aligned numeric columns. Measured from the shipped fonts: the spec's 1.04em/−0.06em Noto Sans Ethiopic join is directionally right but was never derived from the actual metrics (a cap-aligned scale would be 1.083em), and — the load-bearing finding — the shipped HH Lemd Mono v1.102 is NOT genuinely monospaced: its digits advance 462–564 UPM (0.462–0.623em, up to 1.47px/13px drift) and it exposes no tnum/lnum features, so the grammar's promise that "mono + tabular makes the decimal the true alignment anchor" fails in practice ('0.00' renders 27.7px vs '7.77' at 23.3px). HH Lemd stays the single data voice (Noto Sans Ethiopic must NOT carry more — its Latin is borrowed Noto Sans Mono), but the figure alignment must be engineered, not assumed. ahabesha'stypewriter is rejected on three independent hard blockers: non-commercial license, 76-glyph Latin (missing ~19 ASCII), and textured vintage strokes that break tabular discipline and clash with Lemd/Noto Sans Ethiopic's monoline geometry.

**Spec:**

All metrics below are measured from the actual font files (HH Lemd Mono v1.102 OTF via mirror, Noto Sans Ethiopic from Google Fonts OFL), not assumed.

## 0. The measured facts (what the pairing must be true to)

**HH Lemd Mono** (OTF/CFF, unitsPerEm 905 — non-standard; single weight 400, widthClass 5):
- x-height 505 (0.558em), cap 700 (0.774em), typo asc 706/desc −199/lineGap 100. Latin is clean monoline lining.
- DIGIT ADVANCES: 0=564, 1=486, 2=516, 3=509, 4=481, 5=518, 6=543, 7=462, 8=552, 9=543 UPM → 0.462–0.623em. Punctuation narrow: period 234, comma 188, space 230, hyphen-minus 580, true minus U+2212 518, slash 459, percent 552.
- OpenType: GSUB = aalt/ccmp/frac/ordn/salt/sups; GPOS = EMPTY. **No tnum, no lnum.** (`font-feature-settings:"tnum" 1` is a silent no-op.)
- Ships its own Ethiopic: 429 codepoints (356 Ethiopic + 61 Ext + 12 Ext-A), fidel band baseline→700 (exactly its cap line), proportional fidel advances (ሀ 585, ረ 480, ጨ 757, ዊ 598). "Mono" is a styling claim, not a metric.

**Noto Sans Ethiopic** (Google Fonts, OFL 1.1, Behailu Barento/typehabesha, UPM 1000, weight 400):
- TRUE monospace: every glyph in the whole font — Latin, fidel, punctuation, wordspace ፡ — advances exactly 600 (0.600em). Its Latin is literally Noto Sans Mono (A top 717, a top 546, x-height 0.536 per Noto; Noto Sans Ethiopic's OS/2 sxHeight is 500). Its fidel band runs baseline→714 (0.714em), no descenders (yMin 0), drawn specifically for columnar/terminal duty.

**ahabesha'stypewriter** (yoniX 2019): license free for personal use ONLY (commercial requires author authorization); ~331 glyphs = 255 Ethiopic (~66% of the block — incomplete) + 76 Basic Latin (~19 ASCII missing); textured serif mono drawn from 1970s Olympia International typewriter scans.

## 1. Do HH Lemd + Noto Sans Ethiopic coexist in the terminal? — YES, as a two-font script partition, with three rules and one correction

Compatible traits: both single-weight 400, both monoline-geometric, both squared/technical skeletons — the same instrument family, mood-aligned (terminal-calm, no serif, no decoration). The incompatibilities are metric and grid, and they are exactly what the pairing rules must absorb.

- **Vertical metrics.** Lemd cap 0.774em vs Noto Sans Ethiopic cap 0.700em; Lemd x-height 0.558 vs Noto Sans Ethiopic 0.500. In the same em Lemd is visibly bigger — hence the join scale. The 1.04em/−0.06em rule validates: Noto Sans Ethiopic fidel band (0→0.714em) at 1.04 of the Lemd em → top at 0.743em (0.031em below Lemd's cap), and after the −0.06em vertical nudge the band spans −0.060→0.683em of Lemd — the fidel optical mid sits just under the Lemd x-height-to-cap zone. Directionally correct and stable at every size (both factors scale with em). Correction: the true cap-aligned scale is 0.774/0.714 = 1.083em, not 1.04em; the 1.04em was tuned to nothing. The undersize is 0.40px at 13px (invisible) but 1.2–1.6px at --ts-hero 40–52px (visible) — which is moot only because the hero is single-script and must stay that way.
- **Grid behavior.** Noto Sans Ethiopic is a rigid 0.600em grid; Lemd is proportional. A cell like "ዶላር USD/ETB 128.40" thus has two cadences: fidel snapped to a fixed grid, Latin codes and digits proportional. This is acceptable ONLY if fidel are labels (left, never in a numeric column) and Latin digits right-align to the decimal. You cannot line a fidel column up against a Latin column by width — never try; alignment is by role, not by measure.
- **The script-exclusivity rule is mandatory.** Noto Sans Ethiopic's Latin is Noto Sans Mono — if any stack fallback puts Latin/digits in the Noto Sans Ethiopic slot you inject a second Latin design (0.536 x-height, 600-grid) into Lemd's proportional Latin. And HH Lemd owns its own 429-codepoint Ethiopic at 1em/0-nudge with fidel already cap-matched — so the terminal has THREE latent fidel voices. Rule: one fidel owner per table (Noto Sans Ethiopic for terminal, by spec), one Latin owner (Lemd), no cross-over, no fallback that mixes them in one line.
- **Optical coherence of one mixed table: YES**, under the four rules above (fidel = left labels, digits = right decimal-aligned, uniform 1.04em/−0.06em join, both 400). The two faces read as one instrument because they share stroke construction; the different grid cadences are a feature (they visually separate the fidel word from the Latin instrument), not a defect.
- **One open question the pairing cannot settle from metrics:** whether the graft is even necessary. HH Lemd already contains fidel that are cap-exact to its own Latin. The 1.04em Noto Sans Ethiopic graft exists because the spec author never measured Lemd's Ethiopic. Specimen-compare "ዶላር ዩሮ ብር" set in Lemd-native (1em, baseline) vs Noto Sans Ethiopic-grafted (1.04em/−0.06em) side by side at 13px before freezing the rule; if Lemd's fidel drawing holds up, the entire join subsystem collapses to "use Lemd for everything in the terminal," which is strictly more coherent (one font, one UPM, one baseline).

## 2. HH Lemd vs the numeral grammar — the tabular claim FAILS as written; figures are proportional-lining

- Figures ARE lining (tops at 699/905 ≈ cap, bottoms at −2) — `lining-nums` is satisfied by construction.
- `tabular-nums`/`tnum` is NOT satisfied: no tnum/lnum feature exists, and digit advances are not equal. Max per-digit drift = 102 UPM = 1.47px at 13px.
- Demonstrated failure of the grammar's alignment anchor: at 13px right-aligned on the decimal, '0.00' renders 27.7px vs '7.77' 23.3px (4.4px apart — the decimal points do not share a column); '128.40' vs '999.99' drift 1.7px. Consecutive rows of real rate values misalign by ~1–2px, and a full column of "0.00 / 1,234.56 / 7,777.00" by up to ~6px. For a terminal whose entire pitch is "pixel-calm exact alignment," this is a visible defect.
- Assessment: HH Lemd is a monoline PROPORTIONAL data face misnamed "Mono" — good digit skeletons, wrong metric discipline for decimal-aligned columns. The grammar's `font-feature-settings:"tnum" 1` is a silent no-op that must be struck.
- Ranking of fixes: (a) best — re-verify the licensed font.et build; this measurement is the mirror OTF v1.102 and the license is unlisted anyway, so the figure question and the license question are the same fork; (b) if confirmed proportional, enforce alignment structurally: right-align the cell to the decimal and wrap each figure in a fixed 0.625em advance container, OR (c) assign numeric columns to a true mono — but the only true mono in the confirmed set is Noto Sans Ethiopic, whose Latin is generic Noto Sans Mono and would erase Lemd's digit identity; treat that as a downgrade, not the default. Whatever the choice, the spec must state measured reality ("HH Lemd figures are proportional-lining; alignment is engineered, never assumed") instead of the current false promise.

## 3. ahabesha'stypewriter — REJECT as a terminal voice; three independent hard blockers

1. License: personal-use/non-commercial only, commercial needs author authorization — a shipping bilingual terminal cannot carry it, and it is the only candidate outside the OFL family.
2. Coverage: 76 Basic Latin glyphs (~19 ASCII missing) and 255/384 Ethiopic. Terminal units ("ETB", "/lb", "%", "—", "( )") would render tofu; incomplete fidel breaks the wordmark and every label. Fatal for data.
3. Metrics/mood: textured, uneven, vintage serif strokes from 1970s typewriter scans — no tabular discipline, irregular stroke weight, and its nostalgic serif mood fights the classical-gallery restraint and reads as a THIRD instrument beside Lemd/Noto Sans Ethiopic's clean monoline geometry. It has no constructional relationship to either face (different designer, era, technique).

Only defensible use: a deliberate "telegram / vintage-feed" editorial flourish OUTSIDE the data layer, at a size where texture is the point — and only after securing a commercial license from yoniX. It must never appear in a table, ticker, or rate cell.

## 4. Terminal ladder verdict — HH Lemd stays the single data voice; Noto Sans Ethiopic must NOT carry more

HH Lemd is the right data voice (its digit identity, monoline skeleton, and the whole "the terminal's calm IS its hierarchy") — with Noto Sans Ethiopic strictly confined to fidel. Do not extend Noto Sans Ethiopic's role: its Latin is borrowed Noto Sans Mono, so any Latin/digit duty it assumes imports a generic 0.536-x-height 600-grid Latin that matches neither Lemd's proportion nor the identity; and its single-weight fidel are drawn for terminals but are script-exclusive by construction. The ladder stays: --ts-head 11px Noto 700 upper / --ts-data 13px Lemd / --ts-hero Lemd / --ts-term 14px (Lemd Latin, Noto Sans Ethiopic fidel at the join). The one correction is §2: the ladder's "tabular" promise is only as good as the figure face, so the figure-alignment engineering and the license verification are prerequisites, not afterthoughts. Also resolve the internal Stage-1 conflict: the typography spec bans Bela Bereka from the terminal and gives the hero to HH Lemd; the live-data section gives the hero to Bela 2.75rem. The data pairing resolves it: hero = HH Lemd (Bela is wordmark-only; Bela on a number is a flagged no-go). And note the licensed-fallback stack if HH Lemd's license cannot be cleared: Noto Sans Ethiopic (OFL) + Noto Sans Mono (OFL) already cover the full mono job; Lemd is the optional upgrade that earns its keep via digit identity, not via monospacing.

## 5. No-go pairs in data contexts

- Bela Bereka + numerals in the terminal (banned: calligraphic 700, proportional figures, display-only; wordmark floor 1.25rem only).
- Lemd Latin + Noto Sans Ethiopic Latin in one line (two Latin designs: Noto 0.536 x-height vs Lemd 0.558, incompatible grids).
- Lemd Ethiopic + Noto Sans Ethiopic Ethiopic in one table (duplicate fidel designs with different advances — one fidel owner per table).
- ahabesha'stypewriter with anything in data (license + coverage + texture).
- Noto Sans Ethiopic inside mono cells (body face, breaks the 11/13 mono column rhythm; legal only as --ts-head labels).
- Any fidel below 11px (Ethiopic floor) and any mixed-script line at display size (single-language rule).
- Ticker triangles inside tables (▲▼ are ticker-only; tables carry signed strings with the true minus U+2212).


## Bilingual Ge'ez/Latin type pairing — Ethiopian Classical Design Language terminal (Bela Bereka / HH Lemd Mono / Noto Sans Ethiopic / Noto Sans Ethiopic + 7 candidates)

**Verdict:** The four-face core is a CLOSED, coherent pairing system — adopt nothing into it. The dominant pattern, stated as law: at every level except mono data, the correct pair is THE SAME FACE carrying both scripts. At display, Bela Bereka's own Ethiopic cut carries Amharic and Bela's Latin cut carries English, so no cross-face pairing ever has to happen at display size — that is why one-language-at-a-time is enforceable at zero cost. At body and label, Noto Sans Ethiopic carries both scripts, metrics engineered together, so inline glosses need no size-adjust. The ONLY true cross-face Ge'ez/Latin pair is Noto Sans Ethiopic (Ge'ez) + HH Lemd Mono (Latin) inside the mono data context — and that pair rests on an unverified metric assumption (Noto Sans Ethiopic is drawn against Noto Sans Mono's geometry; Lemd's x-height/cap-height and license are unverified). The permanent display pair Noto Sans Ethiopic ማለዳ + Bela Bereka Maleda is ENDORSED but only as a semantically-redundant fixed lockup (both words mean "daybreak" — the same utterance in two scripts, which is what licenses a cross-script moment), with a corrected size-adjust: the Lemd-calibrated 1.04em/−0.06em data rule does NOT transfer to Bela's calligraphic metrics, so ማለዳ must be hand-calibrated to ~1.06–1.12em of the Bela em, baseline-aligned, zero shift. Danger pairs are real and specific: calligraphic/COLR Ge'ez beside neutral Latin (Manuscript Zemen), serif Ge'ez inside sans body (Zemenay), the two-Bela trap (Hidase), textured mono in the calm terminal (typewriter), and any second display voice (Agbalumo, Monolithic, Waldba as a family).

**Spec:**

PAIRING LAYER SPEC — bilingual Ge'ez/Latin, level by level, with metric-matching rules, danger pairs, and the one-language rule.

GROUND TRUTH (verified): Noto Sans Ethiopic's Ethiopic was drawn from the ground up against Noto Sans Mono's geometric dimensions; its Latin is leveraged from Noto Sans Mono (TypeDrawers, Behailu Barento / @typehabesha). This makes the ENTIRE cross-face metric apparatus a dependency on Lemd's optical parity with Noto Sans Mono — not a given.

LEVEL-BY-LEVEL PAIRS:

1) DISPLAY HEADLINE (h1 40–60px, pull-quote 22–28px, hero 44px).
Pair: Bela Bereka 700 Latin ↔ Bela Bereka 700 Ethiopic — THE SAME FACE, scripts swapped by data-lang toggle. There is NO cross-face display pair, and none should be invented. Bela's Latin and Ethiopic cuts share one pen/brush logic, one baseline, one stroke energy: a manuscript switching scripts keeps one hand writing. Any two-face display pair (Zemenay serif Ethiopic + Bela Latin) puts two hands on the page. Metrics: single-language only; Amh lh 1.16 (×1.11), max-width 24ch, text-wrap:balance. The ×1.11 display leading is non-negotiable — at 40–60px, Latin 1.05 leading clips the 6th/7th-order vowel marks that overhang the fidel band. The --ts-hero number (Lemd, 40–52px) is pure Latin digits and is NOT a pair — one display voice per viewport: either the Bela headline or the Lemd hero figure, never both.

2) WORDMARK — the permanent bilingual pair (ASSESS).
Pair: Noto Sans Ethiopic 400 ማለዳ + Bela Bereka 700 Maleda, 1.25rem fixed lockup, 0.6em script-gap, baseline-aligned, zero vertical shift. VERDICT: ENDORSED, on three load-bearing conditions.
(a) Semantic redundancy is the license: ማለዳ and Maleda are the SAME word ("daybreak") — a transliteration pair, not two languages colliding. A reader parses it as one name in two scripts, which is the single legitimate waiver of the display-mixing ban. It is a mark, never a sentence.
(b) The mood counterpoint is the identity's thesis in two glyphs: Bela's warm calligraphic bold = the classical gallery; Noto Sans Ethiopic's neutral mechanical mono (its name, ሕብር, means "thread/warp" — the interlace) = content. This is WHY Noto Sans Ethiopic, not Bela's own Ethiopic cut: a same-face calligraphic lockup would read as a LOGOTYPE, and the identity has no logo. The mono Ge'ez keeps it "two type elements joined," not a logo.
(c) METRIC CORRECTION (the spec's "1.25rem, no adjust" is wrong in the other direction): the 1.04em/−0.06em rule is calibrated to Lemd's cap/x-band via Noto Sans Mono. Bela's calligraphic Latin has a taller cap and higher stroke energy. At a fixed 20px lockup, Noto Sans Ethiopic 400 next to Bela 700 is optically lighter and shorter — Maleda dominates. Fix: one-time hand-calibration of Noto Sans Ethiopic against Bela's MEASURED x-height: set ማለዳ at ~1.06em (Maleda-dominant, preserves non-logotype — recommended) up to ~1.12em (co-equal mark), baseline-aligned, zero shift. This is safe as a one-time tune because the lockup is a fixed size and never has to hold across a ladder. Note: 20px is below Bela's 22px reading floor, but that floor governs reading text; a fixed lockup is brand geometry — acceptable, but never scale the mark below 1.25rem and never set it lowercase.

3) SUBHEAD / SECTION-CHIP (11px = Ethiopic floor).
Pair: Noto Sans Ethiopic 700 ↔ Noto Sans Latin 700 — SAME FACE, both scripts, same size, 0.5em script-gap, line resolves --lh-am. At 11px this is the ONLY safe way to mix scripts: one family whose Ethiopic and Latin metrics were engineered together, so the fidel band and Latin x-height share a plane with zero size-adjust. Do NOT use Noto Sans Ethiopic inside Latin chrome — a mono Ge'ez against proportional Noto at 11px is a mono-vs-proportional clash. The fidäl-initial chip (ዜና → ዘ) default is Noto 700 at 11px, quiet; the ACTIVE chip may optionally rise to ONE large fidäl (16–20px, ≥ Bela's Ethiopic floor) in Bela's Ethiopic cut as a lectionary initial — gated to one per viewport, never in terminal tables. LABEL GOTCHA: Ge'ez has NO case. The 0.14em uppercase+tracking token is a Latin-only hierarchy device; Amh label twins keep tracking ≤0.02em (wide-tracked fidel break the script's connected optical rhythm and read as a broken word).

4) BODY (17px; inline gloss).
Pair: Noto Sans Ethiopic 500 ↔ Noto Sans Latin 400 — SAME FACE; only the weight steps up for the inline Ge'ez accent. Metrics: 1em, natural baseline, ink color (never accent), 500 weight, glossed once with 1px saffron underline, containing paragraph takes --lh-am (1.85 body). This pair is invisible when right: Noto's Ethiopic and Latin share a baseline and rhythm by construction, so a gloss needs no nudge. If you ever feel the urge to nudge an inline gloss, that is the signal you are using the wrong Ge'ez face (Zemenay or a calligraphic face in body).

5) DATA / TERMINAL (13px mono) — the ONLY true cross-face pair.
Pair: Noto Sans Ethiopic 400 (Ge'ez) ↔ HH Lemd Mono 400 (Latin numerals + literals), exclusively inside the mono context. Metrics: Noto Sans Ethiopic at 1.04em of the Lemd em, vertical-align −0.06em, margin-right 0.4em, panel-mut on panels; at 13px → fidel 13.52px, nudge −0.78px. Join on the baseline, never x-height; the −0.06em is a fixed offset that holds across both ladders (11→60px). DEPENDENCY (this is the whole system's weak joint): Noto Sans Ethiopic is drawn to Noto Sans Mono's geometry, so the 1.04em/−0.06em is a guess at optically matching LEMD's cap/x-band. If Lemd's x-height/cap differ from Noto Sans Mono's, the fidel band sits high or low and column alignment drifts — must be MEASURED, not assumed, and re-derived if they differ. Terminal contains no other pair: --ts-head (11px Noto 700) is Latin chrome; Ge'ez in the terminal is only the Noto Sans Ethiopic data accent and the currency identity word (ዶላር). Bela banned; no Ge'ez below 11px.

DANGER PAIRS (specific failure each):
1. Ge'ez Manuscript Zemen ↔ Noto Latin — the calligraphic-vs-neutral clash, cubed by COLR: the face carries pigment INSIDE the glyphs, violating the color laws (gold ≤3%, one accent per viewport, chroma only in hairlines/accents) by injecting gold/madder into every character. Authentic manuscript texture against Noto's uniform sans reads as "a manuscript pasted into a UI." Forbidden except a single monochrome illuminated initial at boot, and only with the color layer stripped.
2. 8. Script-mixing at display (structural, even with good faces): Ge'ez has no case (one optical size) while Latin caps create a second; fidel-band vs cap-height needs fragile size-adjust at 40–60px; measure collapses (24ch Ethiopic vs 30ch Latin); text-wrap:balance breaks. This is exactly why one-language-at-a-time is law.

ONE-LANGUAGE-AT-A-TIME DISPLAY RULE — restated precisely: it is "one display VOICE per line." Because Bela carries both scripts, the Amh headline uses Bela's Ethiopic and the Latin headline uses Bela's Latin — same face, so no pairing ever occurs at display size. The bilingual pair is allowed in exactly three situations: (1) the wordmark lockup (Noto Sans Ethiopic+Bela, 1.25rem fixed) — semantically redundant + image-like, not reading; (2) the boot title block — a COMPOSITION, not a mix: Amharic title + English line + Ge'ez chip, each element single-script, composed in space; (3) label/subhead scale (≤11px, Noto same-face, 0.5em gap) — invisible same-face engineering. Forbidden: any line ≥1rem carrying both scripts — except the terminal's mono data-accent join (Noto Sans Ethiopic at 1.04em inside a Lemd cell), which is below the display threshold and is the one sanctioned cross-face join.

ADOPTION VERDICT: adopt nothing into the core. The four faces form a closed system: Bela (both scripts) display, Noto (both scripts) body/label, Noto Sans Ethiopic+Lemd (cross-face, mono-only) data. Each candidate threatens a different pillar — color law (Manuscript Zemen), voice coherence (Zemenay, Waldba), calm (typewriter), mood+license (Monolithic, Agbalumo), scarcity (Hidase). Only conditional interest: Bela Hidase as a Bereka replacement if license clears and a weight range is wanted — never as companion. Zemenay is worth a separate "print edition" spec, not this terminal.

## Type pairing & hierarchy — which faces work together for the Ethiopian Classical Design Language (bilingual news/exchange-rate terminal, light+dark)

**Verdict:** The pairing is a CLOSED system and it is already engineered, not selected: four faces fill four slots (Bela Bereka = display; Noto Sans Ethiopic = body/UI, the only face below 1rem; HH Lemd Mono = every numeral; Noto Sans Ethiopic = mono Ge'ez), and the two ladders (editorial base 16px ×1.25; terminal base 13px mono) cross at exactly two shared steps — 11px and 13px. There is no open display-companion slot and no open body slot, so most "pairing" is metric-engineering (the Lemd+Noto Sans Ethiopic band join; the Noto+Lemd inline-numeral crossing) and almost none is face-selection. Of the nine candidates, exactly ONE (Bela Hidase) is architecturally harmonious — same designer, same calligraphic DNA, so it extends the existing display voice instead of adding a new one; it is a CONDITIONAL ADOPT. Every other candidate duplicates an owned slot (a second display, a third mono), fails the mood test, or fails license, and none enters the pairing as-is. Two internal spec conflicts must be adjudicated by the pairing layer before the system ships: (1) the boot sequence sets the wordmark in Bela at 1.15rem with 0.14em letter-spacing, contradicting the typography deep-dive's wordmark floor (1.25rem) and its never-track-Bela law — resolve to 1.25rem, tracking 0; (2) the data-view "hierarchy" section puts the headline painting's HERO FIGURE in Bela Bereka 700 at 2.75rem with "proportional figures," contradicting both "Bela is banned from the terminal" and "HH Lemd owns every number, even big ones" — resolve to ts-hero in HH Lemd 400 tabular (#FBF3DB), never Bela. Two licenses remain unverified: HH Lemd Mono (in-system, flagged pending) and Bela Hidase (adoption blocked until OFL confirms).

**Spec:**

TYPE PAIRING & HIERARCHY — the pairing layer

## 0. The working model: pairings are metric joins, not face selections
The deep-dive fixes four faces into four roles and two ladders that cross at 11px and 13px. A "pairing" in this system is one of exactly five legal configurations, four of which are joins (two faces on one line) and one of which is a stack (never a shared line):
- LEMD + HIBURMONO — the mono Ge'ez join. Legal everywhere in the mono/data context. Metric-locked: Noto Sans Ethiopic at 1.04em of the Lemd em, `vertical-align:-0.06em`, `margin-right:0.4em`. At 13px that resolves to fidel at 13.52px, shifted down 0.78px so the fidel band sits optically on Lemd's cap/x-band. It is position-invariant across both ladders (holds at every step 10→60px). This works because Noto Sans Ethiopic is strictly monoline with Noto-Sans-Mono-compatible metrics (verified), i.e. the same stroke philosophy as a Latin mono — a textured or high-contrast mono would break the band match.
- NOTO + LEMD — the inline-numeral crossing. A 13px numeral inside 13px prose (or an 11px Noto 700 label crowning a 13px Lemd value) is legal because at 13px Lemd's monoline neutral band and Noto's humanist band are optically compatible, and lining-tabular figures seat on the same baseline. This is the load-bearing "crossing": a number can sit inside prose, a prose label can crown a table, and no rhythm breaks.
- BELA + HIBURMONO — the wordmark lockup ONLY. ማለዳ in Noto Sans Ethiopic + Maleda in Bela 700 at 1.25rem, 0.6em gap, baseline-aligned, zero vertical shift. This is the single permanent two-script display pair and the only place Bela and any Ge'ez face share a line.
- BELA → NOTO — the article stack. Display descends to lead/body/small in the reading order (h1 → pull-quote → lead → body → small), but Bela and Noto never share a baseline; the display floor (22px) and the "Noto is the only face below 1rem" law keep them in different optical bands.
- SINGLE-FACE by design — anything else. Prose is Noto-only; the terminal is Lemd+Noto-head+Noto Sans Ethiopic-fidel only; labels are Noto 700 only.

Any need that does not resolve to one of these five is not a pairing problem; it is a scope change, and the default answer is "freeze."

## 1. THE PAIRING DECISION TREE — given any new type need
Step 0, classify by these questions in order; the first match routes the need:
1. Is it a NUMERAL, price, timestamp, or any columnar figure? → HH Lemd Mono 400, `font-variant-numeric:tabular-nums lining-nums` (`tnum 1` / `lnum 1`). Partner: none. This includes the ts-hero readout — even a 40–52px number is Lemd, never Bela. (Ge'ez label beside it → add Noto Sans Ethiopic per #2.)
2. Is it GE'EZ TEXT inside a mono/data context (currency names ዶላር/ዩሮ, terminal Ge'ez, ticker labels, section chips)? → Noto Sans Ethiopic 400 at 1.04em of Lemd, `vertical-align:-0.06em`, `margin-right:0.4em`, `--panel-mut` on panels, ink otherwise. Partner: HH Lemd. This is the only legal two-face line in the terminal.
3. Is it any TEXT at or below 1rem (labels, chips, captions, heads, footnotes)? → Noto Sans Ethiopic. 700 for the ONE uppercase+tracked label step (11px, 0.14em editorial / 0.12em terminal, one line); 400 for small/caption. Partner: none. Noto is the only face permitted below 1rem, and no Ge'ez may render below 11px.
4. Is it PROSE above 1rem (lead 18–21 / body 17 / small 13)? → Noto 400; inline Ge'ez gloss at exactly 1em, weight 500, ink color, saffron underline once per article. Partner: HH Lemd ONLY when a numeral appears inline (the crossing).
5. Is it a DISPLAY moment (h1, h2, pull-quote, dropcap, wordmark)? → Bela Bereka 700, tracking 0, never uppercase, min 22px (wordmark floor 1.25rem), max 2 display moments per viewport. Single-language (data-lang toggle) — never script-mixed at display. Partner: Noto Sans Ethiopic ONLY in the wordmark lockup.
6. Is it INSIDE THE TERMINAL (rates, ticker, console)? → No display face at all: 11px Noto 700 head + 13px Lemd value + Noto Sans Ethiopic fidel, and one ts-hero number (Lemd, 40–52px). The terminal's calm IS its hierarchy.
7. Is the designer reaching for a NEW face they feel is "missing"? → Ask which slot it fills. If the slot is owned, it is a no-go (see table). If no slot owns it, it is a scope change — freeze it, and do not let a new face sit beside Bela.

## 2. THE NO-GO PAIRING TABLE (binding)
1. BELA + ANY SECOND DISPLAY FACE in the same viewport — Zemenay, Agbalumo, Ge'ez Manuscript Zemen, Monolithic Geez, or any Waldba display. Two displays is a voice collision; the identity permits ONE display voice, and display hierarchy is by SIZE, never by family.
2. BELA IN THE TERMINAL — banned except the masthead wordmark. The terminal runs 11/13 + one ts-hero (Lemd).
3. UPPERCASE + TRACKING ON BELA — calligraphic joins break and presence doubles. Bela is always 700, tracking 0, mixed-case.
4. BELA BELOW 22px (1.375rem) — the brush joins smear below the optical floor; the wordmark at 1.25rem is the single sanctioned exception (a designed lockup, not running text).
5. GE'EZ IN MONO CONTEXT BELOW 11px — 26 fidel + 7 vowel-row marks are illegible below 0.6875rem; `--fs-micro` (10px) is discarded and no Ethiopic renders there.
6. SCRIPT-MIXING AT DISPLAY SIZE — single-language toggle; the wordmark is the ONLY permanent bilingual pair.
7. TWO CALLIGRAPHIC / ORNAMENTED FACES NEAR EACH OTHER — Bela beside Ge'ez Manuscript Zemen, or Bela beside a historical-traditional serif (Zemenay). The "calligraphic display" seat is Bela's alone; a second hand-drawn voice raises the temperature everywhere Bela works.
8. A THIRD MONO — ahabesha'stypewriter (textured vintage), Monolithic Geez, any Waldba mono. The mono system is the metric-locked Lemd+Noto Sans Ethiopic pair; a third mono breaks the 1.04em/−0.06em band join and the pixel-calm ladder.
9. COLR / SELF-PALETTED FACES — Ge'ez Manuscript Zemen ships COLR colors; the palette is theme-controlled (light/dark), so a self-colored font cannot resolve in either theme and violates the 10% accent + gold ≤3% discipline.
10. ANY FACE WITH UNLISTED LICENSE — HH Lemd Mono is the in-system flagged exception (verify before ship); Bela Hidase is blocked until OFL verifies; Monolithic Geez is blocked on proprietary.
11. UPPERCASE+TRACKING ANYWHERE EXCEPT THE ONE LABEL STEP (Noto 700, 0.14em/0.12em) — nine tracked elements collapse to one.
12. ETHIOPIC NUMERALS IN DATA — ፩–፱ are ceremonial/ordinal only; data digits are Lemd tabular Latin. Dates: Latin digits + Ge'ez month + Latin year in Lemd (`9 ነሐሴ 2026`).
13. A NUMERAL IN BELA OR NOTO — HH Lemd owns every number, including the hero readout.
14. ANY DISPLAY FACE BELOW 1rem — Noto is the only face below 1rem.

## 3. THE HIERARCHY LAW
- ONE display face per viewport. Bela is the display face; max 2 display moments (wordmark + h1, or h1 + one pull-quote). Display hierarchy = SIZE only (h1 clamp 40–60px / h2 28–38px / pull-quote 22–28px / wordmark 1.25rem), weight locked at 700.
- HH LEMD OWNS NUMBERS. Every numeral, every terminal figure, the hero readout (ts-hero clamp(2.5rem,4.5vw,3.25rem), lh 1.05, tabular, tracking 0). One big number per view.
- NOTO OWNS PROSE. Lead/body/small/labels; the only face below 1rem. Noto 700 owns the single uppercase+tracked label step; Noto 500 owns inline fidel glosses (1em, ink color).
- HIBUR OWNS MONO GE'EZ — inside the mono/data context only, at 1.04em of Lemd, −0.06em, 0.4em margin-right.
- WHEN TWO FACES MAY SHARE ONE LINE — the shared 11px/13px crossing is the only sanctioned multi-face line, and it is metric-locked in every configuration:
  - Editorial: 11px Noto 700 label crowns 13px Noto small; a 13px Lemd numeral sits inside 13px Noto prose (band-compatible at 13px).
  - Terminal: 11px Noto 700 head + 13px Lemd value; when fidel joins, Noto Sans Ethiopic enters at 1.04em/−0.06em so the fidel band matches Lemd's band — this three-face line (Noto head + Lemd value + Noto Sans Ethiopic fidel) is the ONLY one allowed anywhere and it is metric-locked, not eyeballed.
  - Wordmark: Noto Sans Ethiopic (ማለዳ) + Bela (Maleda) at 1.25rem, 0.6em gap, baseline, zero vertical shift — the only permanent two-script display pair.
- Any line carrying Ge'ez resolves `--lh-am` (Amh leading = Lat ×1.09 body / ×1.11 display; resolved body 1.7/1.85, small 1.5/1.64, lead 1.55/1.71, h1 1.05/1.16, h2 1.1/1.22, ts-data 1.6/1.74, ts-term 1.6/1.74). Pure-Latin literals (USD/ETB, timestamps) take `--lh`. Default everything to `--lh-am` in this always-bilingual product.

## 4. MOOD RULES
1. THE CALLIGRAPHIC DISPLAY NEVER SITS BESIDE ANOTHER CALLIGRAPHIC ELEMENT. Bela is the only hand-drawn voice. No second calligraphic face (Ge'ez Manuscript Zemen), no ornamental serif (Zemenay), no textured/vintage surface (ahabesha'stypewriter) in its proximity. When in doubt, the environment around a Bela moment is Noto prose and hairline frames — nothing drawn.
2. RESTRAINT IS THE PAIRING POLICY: two display moments max per viewport; Bela max twice per scroll-viewport; no display in the terminal (except wordmark); accents in the 10%; gold ≤3%; exactly three letter-spacing values in the whole system (0 / 0.02em / 0.14em). A new face is evaluated not for how much it adds but for how much it would raise the temperature in the one place Bela already works.
3. THE TERMINAL'S CALM IS ITS HIERARCHY — near-monochrome 11/13, one hero number, no texture, no third mono, no display.
4. THE THREE-QUESTION ADMISSION TEST for any candidate, in order: (a) OFL license? (b) does it fill an unowned slot or duplicate an owned one? (c) does its voice share the "classical gallery / restraint / manuscript" temperature AND stay silent in Bela's presence? A candidate fails the moment it raises the temperature where Bela works.
5. SCRIPT MOOD: display is single-language (data-lang toggle); the wordmark lockup is the single sanctioned exception and it is a fixed, designed artifact — never re-derived in a header, never tracked.

## 5. CANDIDATE VERDICTS
- BELA HIDASE (same designer as Bela Bereka, ExtLt→ExtBd, license unlisted) — CONDITIONAL ADOPT; the only harmonious candidate, because it is the same voice. It extends the display slot's weight axis without adding a second display family: 700 owns h1/h2, a lighter/mid cut owns the wordmark Latin and pull-quote, giving display hierarchy within one family. Adopt ONLY if (a) license verifies OFL, (b) the Ethiopic cuts exist across the range (Latin-only weights would break the single-language display rule), and (c) light cuts preserve the brush joins. If any condition fails, stay with Bela Bereka 700 as the only display cut. Regardless: no display below 22px, none in the terminal, full range never shipped into the UI.
- ZEMENAY (OFL, 2668 glyphs, editorial serif-ish) — DO NOT ADOPT into the pairing; place on the reserve shelf. It fills no unowned slot (the editorial ladder is complete: Bela display + Noto body), it is a fourth voice, and a serif's historical-traditional mood overlaps Bela's calligraphic-traditional seat — two "heritage" voices is the mood no-go. ### The three-face crossing — Noto 700 head + HH Lemd value + Noto Sans Ethiopic fidel co-present on one line (the system's spine, unspecced).

**THE THREE-FACE CROSSING — operative spec**

**0. Scope.** This is the only legal three-face line, and it renders in exactly three contexts: the 40px ticker band, table heads, and empty-state lines. The 11px Noto 700 label step never appears without a 13px value beneath or adjacent; the fidel joins only the Lemd value, never the label. Metrics below are binding everywhere the line renders.

**1. The atomic join token `[data-join]` (the pairing-chart entry).** One Lemd numeral + its Noto Sans Ethiopic fidel, declared a single inline unit: `display:inline-block; white-space:nowrap; vertical-align:baseline`. Lemd 400, `font-variant-numeric:tabular-nums lining-nums`, tracking 0. Noto Sans Ethiopic 400 at `font-size:1.04em` of the Lemd em (13.52px at 13px), `vertical-align:-0.06em` (−0.78px), `margin-right:0.4em` (5.2px) when fidel precedes numeral, `margin-left:0.4em` when it follows; the −0.78px shift seats the fidel band on Lemd's cap/x-band. The token never wraps, never fragments, never interpolates letter-spacing.

**2. The 40px ticker band (2.5rem).** Fixed `height:2.5rem`, `overflow:hidden`, flex row, `align-items:baseline` (never center). The baseline is the 13px Lemd line box; the 11px Noto 700 label rides that same baseline via `line-height:13px`, so label cap-line and value x-band share one optical line. Band rhythm: `padding-block:13.5px` centers the 13px line; label tracking 0.14em editorial / 0.12em terminal, uppercase, single line. Moving ribbon: motion is `translate3d` on a GPU layer; `vertical-align` is layout-time, and horizontal transforms never re-layout, so the −0.06em band match is preserved exactly — the join holds at 13px in motion. Never animate font-size, letter-spacing, or vertical-align.

**3. Flowing ticker vs static table.** Identical metrics in both; only the layout context differs. Ticker: tokens laid on the baseline, strip `overflow:hidden`, a token at the cut edge clips whole — never split mid-`[data-join]`. Table: the same token per cell, `vertical-align:baseline`; when fidel and numeral occupy adjacent cells, the 0.4em margin collapses to `padding-inline:0.4em` on the fidel cell. Table heads: 11px Noto 700 label crowns the 13px value; a head carrying fidel renders Noto Sans Ethiopic alone at ≥11px on the label baseline.

**4. Reduced-motion static state.** `@media (prefers-reduced-motion: reduce)`: ribbon `animation:none`, strip freezes showing the latest tokens, `overflow-x:auto`. All join metrics are unchanged (they are layout-time); frozen tokens clip atomically, no partial `[data-join]`.

**5. Empty-state lines.** 13px, `--lh-am`; Noto 400 text + Noto Sans Ethiopic fidel subject + Lemd placeholder em-dash (`–`, never "0") joined via `[data-join]` — one crossing in miniature, the Lemd dash owning the empty value.
